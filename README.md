# 乔本·数果 AI 肠道健康管理 — 工作台

一个**知识库式 + 实时多人协作**的项目工作台。由猪猪侠（WorkBuddy）搭建，覆盖你要的全部模块，数据互通、可分享、可转发。

## 启动
```bash
cd qiaoben-shuguo-ai
npm install        # 已装可跳过
npm start          # 默认 http://localhost:3088
```
> 用托管 Node 运行亦可：`~/.workbuddy/binaries/node/versions/22.22.2/bin/node server.js`
> 改端口：`PORT=8080 npm start`

## 功能模块
| 模块 | 说明 |
|---|---|
| 概览 | **全盘数据大盘**：KPI + 业务链路(渠道→用户) + 计划进度 + 菌群指标概览 + 近期随访/动态 |
| 计划 | 建计划、分解目标、挂任务、看进度 |
| 方案 | AI 写/改/版本管理，关联客户与任务 |
| 执行进度 | 看板式任务流，点击「推进」流转状态；任务带**优先级/说明/超期标红**；支持**领取任务🙋**与**转让给他人**；首页大盘含「待领取任务」专区 |
| 数据反馈 | 分「代理 / 门店 / 客户」三类来源统一反馈，可按来源筛选 + KPI 统计 + 闭环到任务 |
| 客户系统 | **B/C 双端·统一路径**：B 端=省代/市代/区代/门店/合伙人（带渠道层级树）；C 端=终端用户（挂来源渠道）；统一视图看渠道→用户全链路 |
| 媒体库 | 功能文章/健康知识/图片/视频统一管理；可按客户（B/C）**批量推送**，记录已推送对象，数据互通 |
| 团队 | 成员管理 + **邀请其他 WorkBuddy 用户**加入（实时协作），右上角显示在线 |
| 协作与分工 | 成员工作负载对比 + 分工看板；**任务/方案/AI 均可一键改派**；**超期与负载偏高自动预警** |
| 专家与工具 | 沉淀专家与可调用的工具 |
| AI 任务台 | 发起任务→交给猪猪侠→结果归档→一键转方案 |
| 学习库 | 4 大类（乔本肠道管家 / 门店SOP / 代理与合伙人 / 短视频AI）+ 总纲；每课含**时长⏱**与**考核📝**，统一统计学习时长、考核平均分、通过率与成员排行榜 |
| 动态 | 全员操作时间线（实时） |

## 数据互通逻辑
- 任务 → 挂在「计划」下，进度回填计划完成度
- 方案 → 可关联「客户」「任务」
- 数据反馈 → 绑定「客户」与「任务」，形成干预闭环
- 媒体库 → 素材可**推送给任意 B/C 客户**，推送记录沉淀在素材上，便于追踪触达
- 任务 → 支持**领取(todo→我)/转让(ownerId 改派)**，协作成员自助认领，实时同步
- AI 任务 → 产出可一键转为「方案」或回写进度
- CRM 串联全局：客户能看到其方案、反馈、关联任务

## 多人实时协作
- 后端用 WebSocket 广播，任何人的增删改**全员即时同步**，无需刷新。
- 右上角可切换「当前操作者」，在线成员头像实时显示。

## AI 怎么接（已按你的选择：用 WorkBuddy 内置能力）
- 在「AI 任务台」发起任务 → 点「交给猪猪侠」→ 复制结构化指令 → 在 WorkBuddy / 猪猪侠 会话执行 → 结果回填本页并归档。
- 预留扩展位：未来若要直连自有模型，可在 `server.js` 的 `POST /api/aiTasks/:id/run` 里改为调用你的 endpoint。

## 客户系统：B 端 / C 端 · 统一路径
- **B 端（渠道/代理）**：`省代 → 市代 → 区代 → 门店 → 合伙人`，可设上级渠道形成层级树；每个 B 端自动统计「下游门店数」「带来的 C 端用户数」。
- **C 端（终端用户）**：记录来源渠道（来自哪个 B 端），形成「渠道带用户」的闭环。
- **统一路径视图**：在「客户系统」点「统一路径」标签，看到所有渠道及其带来的 C 端用户，数据全互通、统一管理。
- 方案、数据反馈、AI 任务均可关联任一 B/C 客户，跨模块联动。

## 团队：邀请其他 WorkBuddy 用户协作（名字即身份，免注册）
- 在「团队」页点 **🔗 邀请 WorkBuddy 用户** → 复制邀请链接（形如 `https://你的域名/?join=1`）发给队友。
- 对方打开后**只需输入自己的 WorkBuddy 名字**即可申请加入，**无需注册、无需密码**。
- **权限分级（默认最严格）**：
  - **未审批（只读）**：登录后**不能进行任何操作**——删除 / 编辑 / 下载 / 转发 / 推送 / 导出一律不可用（仅可浏览数据、并修改自己的名字）。
  - **改名即申请**：点右上角 **✏️ 改名**（未审批时标题为「修改名字并提交申请」）→ 可改显示名或 WorkBuddy 名字 → 点「提交申请」即向管理员申请操作权限（后端自动生成一条待审批申请，改名也会重映射历史贡献归属）。
  - **审批通过 → 协作者**：你（管理员）在右上角「📋 审批」通过 → 对方变为协作者，解锁全部操作（编辑 / 删除 / 下载 / 转发 / 推送 / 导出）。
- 说明：本工作台是独立实时协作应用，通过「名字 = 身份」+ 审批实现跨用户协作；WorkBuddy 原生账号体系的深度登录需在 WorkBuddy 平台侧配置，此处用可分享链接 + 名字即可接入。

## 分享 / 转发 / 推送
- 点右上角「分享 / 转发」（仅协作者/管理员可见）：
  - **复制访问地址**发给团队成员 → 部署后公网即可多人协作。
  - **导出数据**(整库 JSON) / **导入数据**：用于备份、换环境迁移（仅协作者/管理员可操作）。
- **📤 推送条目给成员（协作者/管理员）**：右上角「📤 推送」→ 选条目 + 勾选接收成员 + 附言 → 对方在「📥 收件箱」收到。
- **📥 收件箱 + 保存为专项任务**：成员在收件箱可「打开」（深链直达条目）或「💾 保存为专项任务」——下载 `.md` / `.json` 包，导入**自己的 WorkBuddy** 即成为其专项任务，用自己的 AI 能力继续修改（保存/下载需对方已通过审批）。
- 说明：第三方网页无法直接写入他人 WorkBuddy 账号，因此用「导出包 + 深链」桥接：对方在自己 WorkBuddy 打开链接或导入文件，即与其账户 AI 能力绑定。

## 部署到云端（脱离 Mac，24/7 可用）
本仓库已做成**云原生就绪**：绑定 `0.0.0.0`、端口/数据路径/密钥全部走环境变量、内置 `/api/health` 探活。

**环境变量（均可选，有默认值）**
| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `3088` | 监听端口（PaaS 用 8080/3000 等） |
| `HOST` | `0.0.0.0` | 监听网卡 |
| `DATA_FILE` | `./data/db.json` | 数据文件路径，**容器务必挂卷**（如 `/data/db.json`） |
| `AUTH_SECRET` | 内置默认 | 鉴权签名密钥，生产请改成随机长串 |
| `ADMIN_USERS` | `beau` | 初始管理员用户名（逗号分隔） |

**方式 1 · 任意云主机 / 轻量服务器（Docker，推荐）**
```bash
docker compose up -d --build
# 或： docker build -t qiaoben . && docker run -d -p 8080:8080 -v qiaoben-data:/data --restart unless-stopped qiaoben
```
数据落在命名卷 `qiaoben-data`，重启 / 升级不丢。换端口改 `-p`。

**方式 2 · 免费 PaaS（Render / Railway / Koyeb）**
1. 在 PaaS 导入本 GitHub 仓库（已含 `Dockerfile` / `render.yaml` / `railway.json`）。
2. 新建 Web Service → 选 **Docker** 构建 → 环境变量设 `AUTH_SECRET`（**必改**）、`PORT=8080`、`DATA_FILE=/data/db.json`。
3. ⚠️ 免费版**无持久磁盘**：进程重启 / 重新部署会重置数据。要持久化请开 Render Disks / Railway Volume 挂到 `/data`，或用付费 plan。
4. 部署完成后把生成的域名（如 `xxx.onrender.com`）发给队友即可。

**方式 3 · 直接跑（临时 / 内网）**
```bash
npm install && PORT=8080 npm start
```

**方式 4 · HTTPS / 域名（生产环境）**
用 Nginx / Caddy 反代到容器端口并签证书，即可用 `https://你的域名` 访问（实时同步走 WebSocket，反代需支持 Upgrade）。示例 Nginx：
```nginx
location / {
  proxy_pass http://127.0.0.1:8080;
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
  proxy_set_header Host $host;
}
```

**数据说明**：全部业务数据存于 `DATA_FILE`（默认 `data/db.json`，轻量 JSON，零数据库依赖）。备份=拷贝该文件；迁移=导出/导入 JSON（页面右上角「分享 / 转发」也可）。

## 技术栈
Node + Express + ws（实时同步）+ 原生 JS SPA，无构建步骤。数据落盘 `data/db.json`。
